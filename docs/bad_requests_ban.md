# Руководство по мониторингу защиты от ботов

## Что происходит на вашем сервере

На сервере настроена **автоматическая система защиты от ботов** с использованием fail2ban. Система работает в несколько этапов:

### 1️⃣ Сбор данных о подозрительной активности

**Два источника данных:**

- **Django middleware** — автоматически отлавливает подозрительные запросы прямо в приложении (попытки доступа к WordPress админкам, XML-RPC, бэкапам и т.п.)
- **Nginx access log parser** — скрипт `nginx_bad_requests_ingest.py` каждые 10 минут сканирует логи веб-сервера

**Куда попадают данные:**
- Все подозрительные запросы записываются в `/home/ubuntu/undersun/logs/bad_requests.log`

### 2️⃣ Автоматическая блокировка

**Система работает на двух уровнях:**

#### Уровень 1: Fail2ban (реальное время)
- **Критерий:** 5 подозрительных запросов за 1 час → БАН на 24 часа
- **Работает:** круглосуточно, автоматически
- **Реакция:** мгновенная (бот блокируется в течение часа)

#### Уровень 2: Cron-задача (раз в день)
```
*/10 * * * *  — каждые 10 минут парсится nginx access.log
0 3 * * *     — каждый день в 03:00 (сингапурское время) банятся IP по истории
```

**Критерии для cron-задачи:**
- IP должен совершить минимум **3 подозрительных запроса** за последние **30 дней**
- После этого IP блокируется на **24 часа** через fail2ban
- Ловит "медленных" ботов, которые делают 1-2 запроса в день

### 3️⃣ Текущий статус

**По состоянию на момент настройки:**
- Заблокировано: **24 IP-адреса**
- Все заблокированные IP — хостинговые сети (AWS, Azure, OVH, Hetzner и т.д.)
- Это НЕ настоящие пользователи, а автоматические сканеры

## 📊 Команды для мониторинга

### Проверить статус fail2ban

```bash
# Общий статус всех jail
sudo fail2ban-client status

# Статус конкретного jail для вашего сайта
sudo fail2ban-client status undersun-badrequests
```

**Что показывает:**
- `Currently failed` — сколько "провалов" накоплено (но еще не забанено)
- `Total failed` — общее количество зафиксированных нарушений
- `Currently banned` — сколько IP заблокировано СЕЙЧАС
- `Total banned` — сколько всего было забанено за время работы
- `Banned IP list` — список заблокированных адресов

### Анализ логов подозрительных запросов

```bash
cd /home/ubuntu/undersun

# Анализ за последние 7 дней, топ-10 нарушителей
python manage.py analyze_bad_requests --days 7 --top 10

# Анализ за последние 30 дней
python manage.py analyze_bad_requests --days 30 --top 20
```

**Что показывает:**
- Топ IP-адресов с наибольшим количеством подозрительных запросов
- Топ путей, которые пытаются открыть боты
- Топ User-Agent (браузеров/ботов)
- Количество запросов по дням

### Ручная блокировка IP (если нужно)

```bash
cd /home/ubuntu/undersun

# Посмотреть, кого забанить (без реального бана)
sudo /home/ubuntu/venv/bin/python manage.py ban_bad_requests --days 30 --min-count 3

# Забанить (с реальной блокировкой)
sudo /home/ubuntu/venv/bin/python manage.py ban_bad_requests --days 30 --min-count 3 --ban
```

**Параметры:**
- `--days 30` — анализировать последние 30 дней
- `--min-count 3` — банить только если IP нарушил минимум 3 раза
- `--ban` — реально заблокировать (без этого флага просто показывается список)

### Разблокировка IP

```bash
# Если случайно забанили не того
sudo fail2ban-client set undersun-badrequests unbanip <IP-АДРЕС>

# Пример:
sudo fail2ban-client set undersun-badrequests unbanip 1.2.3.4
```

### Просмотр последних банов

```bash
# Последние 20 блокировок в fail2ban
sudo tail -20 /var/log/fail2ban.log | grep Ban

# Последние 50 строк лога fail2ban
sudo tail -50 /var/log/fail2ban.log

# Мониторинг в реальном времени
sudo tail -f /var/log/fail2ban.log
```

## 📅 Расписание мониторинга

### 🔴 Каждый день (5 минут)

**Утром или вечером — быстрая проверка:**

```bash
# Статус защиты
sudo fail2ban-client status undersun-badrequests
```

**На что обратить внимание:**
- `Currently banned` — должно быть 20-50 (если меньше 5 — слабая защита, если больше 100 — возможно, слишком агрессивно)
- `Currently failed` — нормально 100-300 (если больше 500 — много активности)

### 🟡 Каждую неделю (10-15 минут)

**Понедельник или пятница — детальный анализ:**

```bash
cd /home/ubuntu/undersun

# 1. Анализ за неделю
python manage.py analyze_bad_requests --days 7 --top 10

# 2. Проверка последних банов
sudo tail -30 /var/log/fail2ban.log | grep Ban

# 3. Проверка работы nginx парсера
tail -20 /home/ubuntu/undersun/logs/nginx_ingest.log
```

**На что обратить внимание:**
- **Топ IP:** появились ли новые активные сканеры?
- **Топ пути:** какие страницы чаще всего атакуют?
- **Топ User-Agent:** новые типы ботов?
- **Динамика по дням:** есть ли резкие всплески активности?

### 🟢 Каждый месяц (30 минут)

**Первое число месяца — полный аудит:**

```bash
cd /home/ubuntu/undersun

# 1. Полный анализ за месяц
python manage.py analyze_bad_requests --days 30 --top 20

# 2. Статистика fail2ban
sudo fail2ban-client status undersun-badrequests

# 3. Проверка размера логов
ls -lh /home/ubuntu/undersun/logs/
ls -lh /var/log/nginx/

# 4. Просмотр конфигурации
cat /etc/fail2ban/jail.d/undersun-badrequests.conf
```

**Что анализировать:**
- Общий тренд: растёт или падает количество атак?
- Нужно ли изменить пороги (maxretry, findtime)?
- Не переполнились ли логи? (если bad_requests.log > 100MB — можно почистить старые записи)

### 🔵 По необходимости

**Если заметили странную активность:**

```bash
# 1. Детальный анализ конкретного IP
grep "1.2.3.4" /home/ubuntu/undersun/logs/bad_requests.log

# 2. Проверка, забанен ли IP
sudo fail2ban-client status undersun-badrequests | grep "1.2.3.4"

# 3. Ручной бан подозрительного IP
sudo fail2ban-client set undersun-badrequests banip 1.2.3.4

# 4. Разбан ошибочно заблокированного IP
sudo fail2ban-client set undersun-badrequests unbanip 1.2.3.4
```

## 🔍 Как понять, работает ли защита

### 1. Проверьте cron

```bash
crontab -l
```

Должны быть две строки:
```
0 3 * * * cd /home/ubuntu/undersun && sudo /home/ubuntu/venv/bin/python manage.py ban_bad_requests --days 30 --min-count 3 --ban
*/10 * * * * cd /home/ubuntu/undersun && /home/ubuntu/venv/bin/python scripts/nginx_bad_requests_ingest.py --access-log /var/log/nginx/access.log >> /home/ubuntu/undersun/logs/nginx_ingest.log 2>&1
```

### 2. Проверьте логи

```bash
# Должен расти со временем (подозрительные запросы)
tail -f /home/ubuntu/undersun/logs/bad_requests.log

# Должен обновляться каждые 10 минут
tail -f /home/ubuntu/undersun/logs/nginx_ingest.log
```

### 3. Проверьте fail2ban

```bash
sudo fail2ban-client status undersun-badrequests
```

Если `Currently banned` больше 0 — защита работает!

## ❓ Почему "Currently failed" больше, чем "Currently banned"?

**Currently failed** — это количество подозрительных запросов, которые **еще не накопили достаточно нарушений** для бана.

### 📊 Ваши текущие настройки

```bash
maxretry = 5       # Нужно 5 нарушений для бана
findtime = 3600    # За последний 1 час (3600 секунд)
bantime  = 86400   # Бан на 24 часа
```

### Как это работает

**Currently failed: 245** означает, что **за последний час** было зафиксировано 245 подозрительных запросов от разных IP.

**Два уровня защиты:**

#### 🔴 Fail2ban (автоматический, реал-тайм)
- Если IP делает **5 подозрительных запросов за 1 час** → **мгновенный БАН на 24 часа**
- Работает круглосуточно
- Быстрая реакция на активных сканеров

#### 🟡 Cron-задача (раз в день в 03:00)
- Если IP делает **3+ запроса за 30 дней** → **БАН на 24 часа**
- Ловит "медленных" ботов
- Анализирует исторические данные

### Почему 245 failed, но только 34 banned?

Эти 245 "провалов" распределены между множеством IP, и большинство из них:
- Сделали **1-4 запроса** за последний час (недостаточно для бана)
- Делают запросы **с большими промежутками** (не попадают в окно 1 час)
- **Ждут, когда их счётчик обнулится** (через час after последнего запроса)

**Забанены только те IP**, которые:
- Сделали **5+ запросов за час** (fail2ban)
- ИЛИ сделали **3+ запроса за 30 дней** (cron-задача)

## 🛡️ Что блокируется сейчас

**Текущие критерии блокировки:**

✅ Попытки доступа к WordPress админкам (`/wp-admin`, `/wp-login.php`)  
✅ Запросы к `/administrator` (Joomla)  
✅ Попытки скачать бэкапы (`/backup.zip`, `/backup.tar.gz`)  
✅ Запросы к `/xmlrpc.php`  
✅ Попытки найти конфиги AWS, Laravel и т.п.  
✅ Подозрительные User-Agent (curl, python-requests, старые Opera/Chrome)

❌ **НЕ блокируется:** визиты с временем 0:00 (прямые заходы без реферера)

**Почему 0:00 не блокируется:**
- Некоторые реальные пользователи тоже могут открыть и сразу закрыть страницу
- Нужны дополнительные критерии (проверка загрузки CSS/JS, частота запросов, заголовки браузера)
- Риск заблокировать настоящих посетителей

## 🚨 Что делать, если забанили не того

```bash
# 1. Посмотрите список забаненных
sudo fail2ban-client status undersun-badrequests

# 2. Разбаньте нужный IP
sudo fail2ban-client set undersun-badrequests unbanip <IP>

# 3. Добавьте IP в whitelist (чтобы не банить в будущем)
# Отредактируйте /etc/fail2ban/jail.d/undersun.conf
# Добавьте строку:
# ignoreip = 127.0.0.1/8 ::1 <ВАШ_IP>
```
