⏺ Да, есть несколько идей для борьбы с ботами, которые показываются в Яндекс Метрике как прямые заходы:

  🎯 Стратегии детекции ботов с "прямыми заходами"

  1. Анализ поведенческих паттернов

  - Время на сайте = 0 секунд - бот открыл и сразу закрыл
  - Отсутствие загрузки статических ресурсов - если только HTML без CSS/JS/изображений
  - Слишком быстрый клик - переход между страницами < 1 секунды
  - Отсутствие скроллинга - реальные пользователи скроллят, боты - нет
  - Линейный обход страниц - боты часто идут по порядку /page1, /page2, /page3

  2. Проверка технических заголовков

  - Accept-Language отсутствует или подозрительный - боты часто не отправляют
  - Accept-Encoding - отсутствие gzip/deflate
  - Несоответствие User-Agent и Accept - Chrome заявлен, а заголовки как у curl
  - Отсутствие Sec- заголовков* - современные браузеры их отправляют
  - DNT (Do Not Track) - боты часто не устанавливают

  3. Частотный анализ

  - Слишком регулярные интервалы - каждые ровно 60 секунд
  - Один и тот же User-Agent + разные IP из одной подсети
  - Массовые заходы с одного ASN (хостинговые провайдеры: AWS, DigitalOcean, Hetzner)

  4. JavaScript Challenge (honeypot)

  - Cookie-тест: установить cookie через JS, проверить при следующем запросе
  - Canvas fingerprinting: боты не могут рендерить canvas
  - Скрытые поля формы: боты часто заполняют все поля, включая display:none
  - Событие mousemove/scroll: записать наличие хотя бы одного события

  5. Анализ IP-репутации

  - Проверка через GeoIP - хостинговые датацентры vs residential IP
  - Blacklist-сервисы: AbuseIPDB, IPQualityScore API
  - Проверка reverse DNS - у ботов часто generic hostname типа ec2-xx-xx-xx.amazonaws.com

  6. Интеграция с Яндекс Метрикой через API

  - Вебвизор: анализ записей сессий - есть ли реальные движения мыши
  - Hit API: отслеживать параметры визита (clientID, bounce rate)
  - Session Replay: детектить аномалии в поведении

  🛠 Практические рекомендации для вашей системы

  Что можно реализовать БЕЗ изменения фронтенда:

  1. Расширить middleware для анализа:
    - Отсутствие Referer + время на сайте 0 сек
    - Проверка ASN (хостинговые провайдеры)
    - Анализ последовательности запросов (слишком быстрые переходы)
  2. Логировать дополнительные данные:
    - Все HTTP-заголовки в структурированном виде
    - Время между запросами одного IP
    - Факт загрузки статических ресурсов (CSS/JS)
  3. Scoring система:
    - Каждый признак бота = баллы
    - Сумма > порога = вероятный бот
    - Гибкая настройка весов признаков

  Что потребует небольших изменений фронтенда:

  1. JavaScript beacon:
    - При загрузке страницы отправить AJAX с флагом "JS работает"
    - Записать в сессию/cookie
    - Последующие запросы без этого флага = подозрительно
  2. Honeypot fields в формах:
    - Скрытое поле, которое реальные пользователи не видят
    - Боты заполняют = instant ban

  Что даст наибольший эффект:

  Комбинированный подход: scoring система + JavaScript challenge + IP reputation

  Например:
  - Хостинговый IP (+3 балла)
  - Нет Referer (+2 балла)
  - Нет загрузки CSS/JS (+4 балла)
  - Подозрительный User-Agent (+2 балла)
  - Сумма ≥ 7 баллов = бот → мягкая блокировка (rate limiting, captcha) или логирование
