# Vue для админки AREALISTING: пошаговый план

## Цель и границы

Перенести интерактивные рабочие экраны AREALISTING на Vue 3, сохранив Django Admin как точку входа, систему прав и серверную бизнес-логику. Первый экран — сопоставление карточек и предложений (`matching.html`, `arealisting-matching.js`). Обычные списки моделей Django Admin остаются штатными: их перенос не нужен для первого результата.

Исходное состояние: `matching_view` в `apps/arealisting/admin.py` отдаёт HTML и принимает JSON POST с действиями сопоставления и черновиков; шаблон передаёт начальные данные через `json_script`. Вся клиентская логика одного экрана находится в `static/js/admin/arealisting-matching.js` (около 1150 строк). Стили AREALISTING подключаются непосредственно из `static/css/admin/arealisting-matching.css`; публичный Tailwind pipeline к этим экранам не относится.

## Этапы

### 1. Зафиксировать текущие сценарии и контракт

- Составить перечень состояний экрана: выбор проекта и карточек, поиск, фильтр AVAILABLE/SOLD, выбор полей, защита ручных изменений, предпросмотр, сохранение, создание черновика, пропуск и восстановление предложения, ошибки и повторная попытка.
- Описать форму `matching_data`, JSON-запросы и ответы для каждого `action` в `matching_view`; зафиксировать права Django и CSRF для операций записи.
- Добавить сквозные проверки главных сценариев на уровне Django и браузера: сопоставление, сохранение после предпросмотра, черновик, сохранение выбора фото, отказ сервера. Это страховка при замене старого JavaScript.
- **Готово, когда:** для каждого действия известны вход, ответ, ошибка и ожидаемый результат на экране.

### 2. Подключить отдельную сборку Vue

- Создать отдельный пакет для админки AREALISTING с Vue 3, Vite и TypeScript. Не менять два существующих Tailwind pipeline публичного сайта.
- Настроить сборку JS/CSS в `static/` и manifest для хешированных файлов; подключать ресурсы из Django-шаблона через небольшой template tag или helper. В development использовать Vite dev server, в production — собранные файлы и `collectstatic`.
- Ограничить Vue одним контейнером внутри `admin/base_site.html`. Проверить CSP production для собранных скриптов и стилей; внешний CDN не требуется.
- **Готово, когда:** пустой компонент открывается на отдельном тестовом admin-экране локально и после production build без влияния на остальные страницы.

### 3. Вынести серверный контракт экрана

- Оставить загрузку страницы и начальные данные в Django. Разделить обработку чтения и действий так, чтобы Vue получал предсказуемые JSON-ответы с кодами ошибок, сохраняя существующие сервисы `matching`, `drafts` и проверки прав.
- Для каждого POST передавать CSRF-токен; сервер повторно проверяет выбранные ID, права, актуальность данных и ограничения перед записью. Ключ AREALISTING остаётся только на сервере.
- Согласовать единый формат для ошибок валидации, конфликтов после устаревшего предпросмотра и сетевых сбоев.
- **Готово, когда:** API-контракт покрыт тестами, а текущий экран продолжает работать через прежний путь.

### 4. Перенести экран сопоставления

- Разделить интерфейс на компоненты: выбор карточек и предложений, настройка полей, фильтры, сравнение перед сохранением, создание черновика, выбор фото, итог операции.
- Держать выбор и этап работы в явном состоянии Vue. Сохранить текущий черновик выбора в `sessionStorage` с ключом проекта; очищать его только после успешного сохранения или явного сброса.
- Оставить тексты, доступные состояния кнопок, сообщения об ошибках и ссылки возврата понятными модератору. Предпросмотр должен показывать именно то, что будет отправлено серверу.
- Удалить подключение `arealisting-matching.js` только после проверки функционального соответствия на новом экране.
- **Готово, когда:** модератор может пройти весь путь «комплекс → карточки → проверка → сохранение» и сценарий создания черновика без потери имеющихся возможностей.

### 5. Перенести следующие рабочие экраны по одному

- Экран фото: выбор и исключение материалов, главное фото, полный размер, пересчёт изменений, запуск и отслеживание фоновой загрузки. Сохранить защиту ручных фото и проверку актуальности preview.
- Очередь проверки и рабочая страница: переносить только участки с действительно интерактивным состоянием; таблицы и простые формы могут остаться Django-шаблонами.
- У каждого экрана свой Vue entry point или небольшой отдельный mount; общие компоненты и API-клиент переиспользуются.
- **Готово, когда:** новый экран прошёл те же сценарии и старый JS этого экрана удалён.

### 6. Проверить и выпускать поэтапно

- Запустить Django-тесты AREALISTING, frontend unit-тесты для состояния выбора и браузерные сценарии с учётной записью модератора и администратора.
- Проверить права доступа, CSRF, ошибки сети, повторный POST, устаревшие данные, мобильную ширину и клавиатурную навигацию.
- Выпускать после production build и `collectstatic`, начиная с сопоставления. Проверить загрузку JS/CSS, сохранение и ошибки в браузере; сохранить возможность быстро вернуть прежний шаблон до завершения приёмки.
- **Готово, когда:** модераторы подтвердили основные сценарии на production, ошибки отслеживаются, а неиспользуемые файлы и временный переключатель удалены.

## Порядок первой реализации

Первый рабочий инкремент: этапы 1–4 только для сопоставления. Он даёт заметный результат и проверяет связку Django Admin + Vue + Vite на самом сложном текущем экране. После его приёмки выполнять этап 5 по одному экрану, затем завершить этап 6.
