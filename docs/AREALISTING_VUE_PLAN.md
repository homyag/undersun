# Vue для админки AREALISTING: пошаговый план

## Цель и границы

Перенести весь пользовательский интерфейс раздела `/admin/arealisting/` на Vue 3, сохранив Django Admin как точку входа, систему прав и серверную бизнес-логику. Первый экран — сопоставление карточек и предложений (`matching.html`, `arealisting-matching.js`). Списки моделей Django Admin оставались штатными для первого результата, но входят в итоговый объём переноса.

## Полный охват раздела

Итоговая цель — единый интерфейс на всех рабочих адресах `/admin/arealisting/`, включая страницы моделей. Перенос выполняется по экранам с сохранением текущих URL; общий визуальный каркас можно подключать раньше полной замены форм. Django продолжает проверять права, CSRF, актуальность данных и выполнять операции записи.

1. **Обзор и комплексы:** показатели, поиск и страницы проектов, запуск синхронизации и загрузки предложений.
2. **Работа с фото:** выбор и исключение материалов, главное фото, предпросмотр изменений, массовый импорт, прогресс задания и повтор ошибок.
3. **Проверка данных:** очередь изменений, цены, объекты без связи, готовность карточек к публикации.
4. **Списки и формы моделей:** материалы, предложения, связи, локации, планы оплаты, пропущенные предложения, история обновлений, события, изменения карточек и состояние синхронизации. Для каждого экрана нужны серверные JSON-контракты, фильтрация, пагинация и формы с теми же правами и валидацией.
5. **Проверка и включение:** браузерные сценарии для модератора и администратора, ошибки сети и устаревших данных, мобильная ширина, клавиатура, production build и `collectstatic`; после приёмки удалить резервные скрипты и шаблоны.

Очередность следующей реализации: сначала одиночный предпросмотр фото, затем страница фонового задания и массовый импорт; далее очередь изменений и цены, обзор комплексов, после этого служебные списки и формы. Каждый экран остаётся работоспособным на Django до проверки Vue-версии.

Исходное состояние: `matching_view` в `apps/arealisting/admin.py` отдаёт HTML и принимает JSON POST с действиями сопоставления и черновиков; шаблон передаёт начальные данные через `json_script`. Вся клиентская логика одного экрана находится в `static/js/admin/arealisting-matching.js` (около 1150 строк). Стили AREALISTING подключаются непосредственно из `static/css/admin/arealisting-matching.css`; публичный Tailwind pipeline к этим экранам не относится.

## Этапы

### 1. Зафиксировать текущие сценарии и контракт

- Составить перечень состояний экрана: выбор проекта и карточек, поиск, фильтр AVAILABLE/SOLD, выбор полей, защита ручных изменений, предпросмотр, сохранение, создание черновика, пропуск и восстановление предложения, ошибки и повторная попытка.
- Описать форму `matching_data`, JSON-запросы и ответы для каждого `action` в `matching_view`; зафиксировать права Django и CSRF для операций записи.
- Добавить сквозные проверки главных сценариев на уровне Django и браузера: сопоставление, сохранение после предпросмотра, черновик, сохранение выбора фото, отказ сервера. Это страховка при замене старого JavaScript.
- **Готово, когда:** для каждого действия известны вход, ответ, ошибка и ожидаемый результат на экране.

### 2. Подключить отдельную сборку Vue

- Создать отдельный пакет для админки AREALISTING с Vue 3, Vite и TypeScript. Не менять два существующих Tailwind pipeline публичного сайта.
- Настроить сборку JS/CSS в `static/` и manifest для хешированных файлов; подключать ресурсы из Django-шаблона через небольшой template tag или helper. В development использовать Vite dev server, в production — собранные файлы и `collectstatic`.
- Ограничить Vue одним контейнером внутри `admin/base_site.html`. Проверить CSP production для собранных скриптов и стилей; внешний CDN не требуется.
- **Готово, когда:** пустой компонент открывается на отдельном тестовом admin-экране локально и после production build без влияния на остальные страницы.

### 3. Вынести серверный контракт экрана

- Оставить загрузку страницы и начальные данные в Django. Разделить обработку чтения и действий так, чтобы Vue получал предсказуемые JSON-ответы с кодами ошибок, сохраняя существующие сервисы `matching`, `drafts` и проверки прав.
- Для каждого POST передавать CSRF-токен; сервер повторно проверяет выбранные ID, права, актуальность данных и ограничения перед записью. Ключ AREALISTING остаётся только на сервере.
- Согласовать единый формат для ошибок валидации, конфликтов после устаревшего предпросмотра и сетевых сбоев.
- **Готово, когда:** API-контракт покрыт тестами, а текущий экран продолжает работать через прежний путь.

### 4. Перенести экран сопоставления

- Разделить интерфейс на компоненты: выбор карточек и предложений, настройка полей, фильтры, сравнение перед сохранением, создание черновика, выбор фото, итог операции.
- Держать выбор и этап работы в явном состоянии Vue. Сохранить текущий черновик выбора в `sessionStorage` с ключом проекта; очищать его только после успешного сохранения или явного сброса.
- Оставить тексты, доступные состояния кнопок, сообщения об ошибках и ссылки возврата понятными модератору. Предпросмотр должен показывать именно то, что будет отправлено серверу.
- Удалить подключение `arealisting-matching.js` только после проверки функционального соответствия на новом экране.
- **Готово, когда:** модератор может пройти весь путь «комплекс → карточки → проверка → сохранение» и сценарий создания черновика без потери имеющихся возможностей.

### 5. Перенести следующие рабочие экраны по одному

- Экран фото: выбор и исключение материалов, главное фото, полный размер, пересчёт изменений, запуск и отслеживание фоновой загрузки. Сохранить защиту ручных фото и проверку актуальности preview.
- Очередь проверки и рабочая страница: переносить только участки с действительно интерактивным состоянием; таблицы и простые формы могут остаться Django-шаблонами.
- У каждого экрана свой Vue entry point или небольшой отдельный mount; общие компоненты и API-клиент переиспользуются.
- **Готово, когда:** новый экран прошёл те же сценарии и старый JS этого экрана удалён.

### 6. Проверить и выпускать поэтапно

- Запустить Django-тесты AREALISTING, frontend unit-тесты для состояния выбора и браузерные сценарии с учётной записью модератора и администратора.
- Проверить права доступа, CSRF, ошибки сети, повторный POST, устаревшие данные, мобильную ширину и клавиатурную навигацию.
- Выпускать после production build и `collectstatic`, начиная с сопоставления. Проверить загрузку JS/CSS, сохранение и ошибки в браузере; сохранить возможность быстро вернуть прежний шаблон до завершения приёмки.
- **Готово, когда:** модераторы подтвердили основные сценарии на production, ошибки отслеживаются, а неиспользуемые файлы и временный переключатель удалены.

## Порядок первой реализации

Первый рабочий инкремент: этапы 1–4 только для сопоставления. Он даёт заметный результат и проверяет связку Django Admin + Vue + Vite на самом сложном текущем экране. После его приёмки выполнять этап 5 по одному экрану, затем завершить этап 6.

## Текущий рабочий инкремент

Экран сопоставления реализован как отдельная Vue 3 + TypeScript сборка в `frontend/arealisting-admin`. Он использует существующий JSON-контракт `matching_view`: сопоставление и выбор полей, предпросмотр и сохранение, очередь несвязанных предложений, создание черновика с выбором фото, пропуск и восстановление. Серверные проверки прав, CSRF и сервисы записи остались в Django. Старый экран сохранён как резервный вариант на время приёмки.

Локально: в `frontend/arealisting-admin` выполнить `npm ci && npm run build`, затем открыть нужный экран AREALISTING. В `development.py` Vue включён по умолчанию, поэтому прямые ссылки и меню открывают Vue без `?vue=1`. Для горячей перезагрузки вместо сборки запустить `npm run dev` и задать `AREALISTING_VITE_DEV_SERVER_URL=http://127.0.0.1:5174`. При `AREALISTING_VUE_ENABLED=False` доступен прежний экран; для проверки Vue отдельно добавьте `?vue=1`. В production новый экран включается через `AREALISTING_VUE_ENABLED=True` после сборки и `collectstatic`; если манифеста нет, Django отдаёт старый экран.

Проверено: production build, фронтенд тесты модели выбора, тесты `apps.arealisting.tests.test_matching`, `manage.py check`, браузерная проверка выбора предложения и экрана предпросмотра. Перед включением в production остаётся пройти ручную проверку модератором на реальных данных и этап приёмки из пункта 6.

## Визуальная основа

Для обзора и сопоставления подключены компоненты PrimeVue 4 с темой Aura, на которой основан свободный шаблон Sakai. Цвета темы заданы в `frontend/arealisting-admin/src/theme.ts` по палитре Undersun; компоненты сводки находятся в `OverviewApp.vue` и `MatchingApp.vue`. Обзор получает числа из существующего серверного контекста и сохраняет подробные показатели в Django-шаблоне, поэтому отсутствие собранного Vue-бандла не скрывает рабочие данные. Django Admin продолжает отвечать за вход, права, маршруты и CSRF.

Сборка Vite использует `/static/arealisting-app/` как базовый путь только для production build. Значки карточек встроены в Vue как SVG и не требуют отдельного шрифта. После изменения компонентов запустите `npm run build` в `frontend/arealisting-admin`; в production дополнительно нужен обычный `collectstatic`.

## Текущий шаг полного охвата

Одиночный предпросмотр фото доступен в Vue по `/admin/arealisting/arealistinglistinggroup/<ID>/preview-media/?vue=1` при `DEBUG=True` и готовой сборке. Выбор фото и главного фото управляется Vue; после изменения выбора подтверждение блокируется до серверного пересчёта. POST, fingerprint, права и запуск задания остаются в Django.

Страница фонового задания доступна в Vue по `/admin/arealisting/arealistinglistinggroup/<ID>/media-job/<JOB_ID>/?vue=1`. Пока задание выполняется, она опрашивает защищённый JSON-ответ того же Django view (`?format=json`) и обновляет прогресс без перезагрузки. Ошибки показаны по каждому фото; повтор только ошибок отправляется в прежний защищённый POST. Переходы из Vue-предпросмотра и после повтора сохраняют локальный параметр `vue=1`.

Массовый предпросмотр также перенесён на Vue: после действия «Проверить и импортировать фотографии и планировки» он показывает до 10 групп, количество добавляемых, обновляемых и удаляемых фото, первые выбранные миниатюры и ссылку на настройку каждой группы. Подтверждение сверяет fingerprint каждой группы в Django. Если состав фото изменился, открывается новый предпросмотр той же выборки. Для нескольких групп Vue показывает список поставленных заданий со ссылками на прогресс. Локально массовую версию можно открыть из старого предпросмотра кнопкой «Открыть новый массовый предпросмотр»; в production эти экраны включаются общим `AREALISTING_VUE_ENABLED`. Старые шаблоны остаются резервным вариантом.

Очередь изменений доступна в Vue по `/admin/arealisting/arealistingproject/review-queue/?vue=1` при `DEBUG=True` и готовой сборке. Она показывает ожидающие проверки цен, замечания связанных карточек, события синхронизации, сравнение характеристик, фильтры и пагинацию. Быстрый поиск работает внутри текущей страницы и явно обозначен как локальный. POST-действия «Отметить проверенным» и «Сохранить значение Undersun» по-прежнему проходят проверки Django и возвращают модератора к выбранным фильтрам.

Экран решения по цене также работает на Vue: ссылка из Vue-очереди ведёт на `/admin/arealisting/arealistingpricereview/<ID>/review/?vue=1`. Он показывает текущие и предложенные цены, выбранные предложения, даёт подтвердить или отклонить цену. Сервер перед применением повторно проверяет актуальность предложения; права и сообщения об ошибках остаются в Django. После решения пользователь остаётся на Vue-экране с итоговым статусом.

Список предложений цен доступен по `/admin/arealisting/arealistingpricereview/?vue=1` при `DEBUG=True`. Статусы показывают число записей с учётом поиска и периода, поиск работает по карточке и комплексу, фильтр периода — за всё время, 7 или 30 дней. Сортировка поддерживает новые, старые и наибольшее изменение цены; пагинация выполняется на сервере. Из обзора и очереди ссылка на список сохраняет локальный режим Vue, а после решения можно вернуться к выбранным фильтрам и странице. Прежний Django-список остаётся резервным вариантом. Следующий этап — остальные рабочие списки и формы раздела.

Очередь карточек без связи доступна по `/admin/arealisting/arealistingproject/unlinked/?vue=1` при `DEBUG=True`. Vue показывает карточки для сопоставления и карточки на ручном ведении, фильтры активности, поиск, пагинацию и выбор комплекса. Загрузка предложений и отметка ручного ведения используют прежние POST с правами и CSRF. Локальный режим Vue сохраняется при переходе к сопоставлению, возврате и загрузке предложений. После успешного сопоставления ссылка ведёт в очередь с прежними фильтрами без уже связанной карточки. При отсутствии сборки остаётся прежний шаблон. Следующий шаг полного охвата — оставшиеся служебные списки и формы моделей.

Список материалов доступен по `/admin/arealisting/arealistingasset/?vue=1`, а материал — по `/admin/arealisting/arealistingasset/<ID>/change/?vue=1` при `DEBUG=True`. Есть фильтры состояния загрузки, типа и активности, поиск, полный текст ошибки, ссылка на оригинал и подходящие группы. Vue повторяет загрузку выбранных изображений по одному запросу на файл и показывает результат каждой попытки; за один проход можно выбрать до 10 файлов. Сервер сохраняет прежние проверки типа, состояния и прав. Прежние Django-страницы остаются резервными. Следующий шаг полного охвата — связи с карточками и другие служебные модели.

Список связей с карточками доступен по `/admin/arealisting/arealistinglistinggroup/?vue=1` при `DEBUG=True`. Он показывает готовность, замечания с рекомендуемым действием, фильтры, поиск и переходы к карточке, сопоставлению и фото. Выбор до 10 групп запускает прежний серверный предпросмотр массового импорта или пересчёт. Само подтверждение импорта и проверка состава фото по fingerprint остаются в Django.

Экран группы доступен по `/admin/arealisting/arealistinglistinggroup/<ID>/change/?vue=1`. Он показывает связь, замечания, состояние фото и историю импорта. Название, активность и защиту полей можно сохранить через отдельную серверную форму с проверкой прав и допустимых полей. Связь с карточкой и состав предложений меняются на экране сопоставления; стандартная форма Django остаётся доступной без `vue=1`. Следующий шаг полного охвата — остальные служебные списки и формы моделей.

История обновлений доступна по `/admin/arealisting/arealistingsyncrun/?vue=1`. Список фильтруется по статусу и режиму, ищет номер запуска или текст ошибки и открывает Vue-детали запуска. Детали показывают время, ресурсы, счётчики обработки, ошибку и переход в очередь изменений; возврат сохраняет фильтры и страницу. Права просмотра проверяются Django. Стандартный список остаётся доступным без `vue=1` до общего включения Vue.

Сопоставление локаций доступно по `/admin/arealisting/arealistinglocationmapping/?vue=1`. Список показывает ожидающие и подтверждённые записи, фильтры по режиму и актуальности источника, поиск и серверную пагинацию. В деталях модератор выбирает район, локацию, отсутствие связи или игнорирование и подтверждает результат. Django ModelForm применяет прежнюю проверку обязательного района или локации; сохранение пишет запись в журнал Admin. Возврат сохраняет фильтры. Без `vue=1` при локальном флаге остаётся стандартная Django Admin форма.

История изменений карточек доступна по `/admin/arealisting/arealistingpropertychange/?vue=1`. Список фильтруется по виду изменения, карточке и поиску; ссылка из Vue-группы сразу показывает изменения её карточки. Детальный экран показывает значения до и после, сотрудника, комплекс и ссылку на запуск синхронизации при наличии прав. Возврат сохраняет фильтры и страницу. Django Admin остаётся резервным интерфейсом.

Предложения AREALISTING доступны по `/admin/arealisting/arealistingunit/?vue=1`. Список показывает доступные, проданные и не связанные с группой предложения; есть поиск, фильтры по синхронизации, актуальности источника и комплексу. Детальный экран показывает данные источника и позволяет изменить группу публикации и флаг синхронизации. Сервер разрешает группы только того же комплекса, проверяет права и пересчитывает прежнюю и новую группы в одной транзакции. После смены связи модератору напоминают проверить цену карточки. Старый Django Admin остаётся резервным интерфейсом.

Пропущенные предложения доступны по `/admin/arealisting/arealistingskippedunit/?vue=1`. Список и детали показывают причину, сотрудника, дату, предложение и комплекс. Из обеих страниц предложение можно вернуть в очередь существующим сервисом `restore_units`; POST требует права на сопоставление, актуальный комплекс и предложение без группы. Возврат сохраняет фильтры, а запись о действии попадает в журнал Admin. Удалённые в источнике или уже связанные предложения остаются только для просмотра. В общем списке предложений пропуск отмечен отдельным значком и ссылкой на причину.

Планы оплаты доступны по `/admin/arealisting/arealistingpaymentplan/?vue=1`. Список показывает актуальные и удалённые в источнике планы, поиск и фильтр по комплексу. Детали показывают описание и все поля каждого этапа оплаты, в том числе дополнительные поля источника. Возврат сохраняет поиск, фильтры и страницу. Данные принадлежат AREALISTING, поэтому Vue-экран доступен только для просмотра; права проверяются Django.

Журнал событий доступен по `/admin/arealisting/arealistingsyncevent/?vue=1`. Список фильтруется по виду события, номеру запуска и проверке, ищет связанные предложение, комплекс или карточку. Детали показывают сохранённые данные, статус проверки и ссылки на доступные сотруднику записи и очередь проверки. Возврат сохраняет фильтры и страницу; запись события остаётся только для просмотра.

Состояние синхронизации доступно по `/admin/arealisting/arealistingsyncstate/?vue=1`. Экран отделяет фоновую задачу и общую блокировку от состояний ресурсов, показывает последнюю попытку, время последнего успешного запуска, ошибки и дату, до которой обработаны изменения каждого ресурса. Блокировка старше двух часов отмечается как возможное зависание. Карточка состояния доступна только для просмотра; ссылки на историю запусков показываются при наличии права просмотра.

Связи фото с карточками доступны по `/admin/arealisting/arealistingpropertyasset/`. Vue-список показывает роль фото, карточку, комплекс и наличие созданного изображения; есть фильтры по роли, комплексу и наличию изображения, поиск и пагинация. Детали показывают фото в полном размере, оригинал AREALISTING, файл карточки и переходы к материалу, группе и карточке с учётом прав. Данные доступны только для просмотра; состав фото по-прежнему меняется через импорт группы.

Просмотр отдельного комплекса доступен по `/admin/arealisting/arealistingproject/<ID>/change/`. Vue показывает состояние комплекса, предложения, связи, планы оплаты, материалы, фотографии и подробности источника. Ссылки на связанные разделы зависят от прав сотрудника, загрузка предложений использует прежний POST с CSRF. Из обзора можно открыть комплекс и вернуться к прежнему поиску и странице. В development Vue включён по умолчанию; на production прежняя форма остаётся резервной до включения флага.

Проверка готовности карточки перед публикацией доступна в Vue по ссылке из списка и деталей связи. Она показывает обязательные проверки и предупреждения из существующего сервиса Django, а также действия, доступные сотруднику по его правам. Старый шаблон сохранён при выключенном флаге или отсутствии сборки.

Создание группы из списка связей доступно в Vue. Комплекс и свободная карточка выбираются через поиск, сервер проверяет данные формы и права добавления, затем открывает новую группу для настройки. Старый Django Admin остаётся резервным вариантом при выключенном Vue.

Локации AREALISTING создаются синхронизацией комплексов по `external_id`; ручное создание записи не является рабочим сценарием. Кнопка добавления в старом Django Admin отключена, а Vue-список объясняет, как получить новую локацию и затем сопоставить её с районом или локацией Undersun.

Подтверждение отвязки карточки доступно в Vue из деталей группы и по прежней ссылке в карточке Undersun. Экран показывает последствия действия и отправляет прежний защищённый POST с ID текущей группы. Django повторно проверяет связь под блокировкой, сохраняет историю и возвращает карточку в подбор комплекса; в локальном предпросмотре сохраняется `vue=1`. При выключенном Vue остаётся прежний шаблон.

Проверены основные переходы локального Vue-предпросмотра: боковое меню, обзор, поиск и пагинация комплексов, переход к сопоставлению, список связей, загрузка предложений, события синхронизации и результат сохранения сопоставления. Ссылки и возвраты сохраняют `vue=1`; ссылка «Все комплексы» из списка связей теперь ведёт к обзору комплексов. Следующий шаг — ручная приёмка сценариев на реальных локальных данных.
