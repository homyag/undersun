# Пайплайн: попап по наведению и рассыпанные объекты на карте

Документ описывает план реализации поведения карты каталога, при котором карточка объекта открывается при наведении на маркер, а объекты недвижимости отображаются отдельными маркерами вместо группировки в одну точку.

## 1. Цель задачи

Клиентское ожидание:

- при наведении на объект на карте пользователь сразу видит попап с краткой карточкой объекта;
- объекты не схлопываются в один кластер или одну визуальную точку;
- если несколько объектов имеют одинаковые или близкие координаты, они должны быть визуально разнесены на карте;
- реальные координаты объектов в базе не должны изменяться;
- на мобильных устройствах поведение должно оставаться удобным, так как hover там отсутствует.

## 2. Текущее состояние

Основные файлы:

- `static/js/map/map_core.js` - инициализация MapLibre-карты, источники, слои, клики, hover-состояния, кластеризация, spiderfy.
- `static/js/map/map_popups.js` - сборка HTML попапа объекта.
- `static/js/list/list_map_data_loader.js` - загрузка данных объектов для карты.
- `static/js/list/list_view_toggle.js` - переключение режима списка/карты.

Что уже есть:

- основной GeoJSON source создается с `cluster: true`;
- кластеры отображаются отдельными слоями;
- при клике на кластер карта либо приближает область, либо раскрывает небольшой spiderfy;
- при клике на маркер вызывается `openPropertyPopup(feature)`;
- для точных совпадений координат уже есть базовая эвристика `normalizeCoordinates()`, которая слегка сдвигает объекты по кругу;
- hover-состояние маркера уже есть, но сейчас оно используется для подсветки, а не для открытия попапа.

Проблемы текущего поведения:

- из-за `cluster: true` несколько объектов могут визуально превращаться в один кластер;
- текущий разнос координат работает только для абсолютно одинаковых координат;
- сдвиг координат задан в градусах, поэтому он не идеально стабилен на разных zoom-уровнях;
- попап открывается по клику, а не по наведению.

## 3. Целевое поведение

### Desktop

- Наведение на маркер открывает попап объекта.
- При движении между маркером и попапом попап не закрывается мгновенно.
- При уходе курсора с маркера и попапа попап закрывается с небольшой задержкой.
- Клик по маркеру может оставаться как закрепление/переоткрытие попапа.
- Клик по ссылкам внутри попапа работает без конфликтов с hover-логикой.

### Mobile / Touch

- Hover-логику не включаем.
- Открытие попапа остается по тапу.
- Если карта будет перегружена маркерами, отдельно рассматриваем мобильную нижнюю карточку вместо классического попапа.

### Отображение маркеров

- Кластеры объектов недвижимости отключаются.
- Каждый объект выводится отдельным маркером.
- Объекты с одинаковыми или близкими координатами визуально разводятся вокруг исходной точки.
- Исходные координаты сохраняются в данных объекта и не перезаписываются в базе.
- Визуальный сдвиг должен быть детерминированным: один и тот же объект должен попадать в одно и то же место при повторной загрузке.

## 4. Архитектурное решение

### 4.1. Отключить кластеризацию объектов

В `static/js/map/map_core.js` основной source сейчас создается с кластеризацией.

План:

1. Сделать режим отображения объектов без кластеров.
2. Убрать или условно отключить слои кластеров:
   - `property-clusters-glow`;
   - `property-clusters-ring`;
   - `property-clusters`;
   - `property-clusters-hover`.
3. Упростить обработчики клика по кластерам либо оставить их только за feature flag, если понадобится быстро вернуть старое поведение.

Рекомендуемый подход:

- на первом этапе не удалять весь старый код кластеров физически;
- ввести понятный режим, например `clusterProperties: false`, чтобы безопасно переключить поведение;
- после приемки можно удалить неиспользуемую кластерную ветку отдельной задачей.

### 4.2. Улучшить разнос одинаковых и близких координат

Текущая `normalizeCoordinates()` группирует только координаты с точным совпадением до 6 знаков.

Нужно заменить ее на более устойчивую подготовку координат для карты.

Логика:

1. Берем список объектов с валидными `lat` и `lng`.
2. Не меняем исходные поля `lat` и `lng` в объекте как бизнес-данные.
3. Добавляем отдельные вычисленные координаты для рендера, например `map_lat` и `map_lng`.
4. Группируем объекты:
   - сначала по точному совпадению координат;
   - затем по близости в пределах небольшого радиуса;
   - радиус лучше считать в экранных пикселях после проекции карты, а не только округлением градусов.
5. Для группы из 2+ объектов раскладываем точки вокруг центра:
   - 2 объекта - по разные стороны от центра;
   - 3-8 объектов - окружность;
   - 9+ объектов - спираль или несколько окружностей.
6. Сдвиг делаем детерминированным:
   - порядок сортируем по `id`;
   - угол/позиция зависят от индекса в отсортированной группе.

Важное ограничение:

- сдвигаются только координаты отображения на карте;
- в попапе, URL, админке, фильтрах и базе остаются реальные координаты объекта.

### 4.3. Выбрать уровень сдвига

Нужно избежать двух крайностей:

- слишком маленький сдвиг - маркеры все равно слипаются;
- слишком большой сдвиг - пользователь будет думать, что объект находится в другом месте.

Рекомендация:

- на дальнем zoom сдвиг держать компактным;
- на среднем и близком zoom разводить маркеры заметнее;
- считать сдвиг в пикселях карты и переводить обратно в `lng/lat` через `project` / `unproject`.

Ориентиры:

- 2-4 объекта: радиус 24-36 px;
- 5-10 объектов: радиус 40-64 px;
- 10+ объектов: спираль с шагом 10-14 px.

### 4.4. Сохранить читаемость карты

Отключение кластеров может резко увеличить количество видимых маркеров.

Перед финальной приемкой нужно проверить:

- сколько объектов одновременно приходит в карту;
- как карта выглядит на desktop при полном каталоге;
- как карта выглядит на мобильном;
- не перекрывают ли маркеры важные районы;
- не проседает ли FPS при pan/zoom.

Если объектов слишком много:

- грузить/показывать только объекты в текущих bounds карты;
- ограничивать число маркеров на дальнем zoom;
- использовать более компактный стиль маркера;
- показывать подсказку о необходимости приблизить карту;
- оставить кластеризацию только на очень дальнем zoom, если клиент согласится.

## 5. Hover-попап

### 5.1. Переиспользовать существующий HTML попапа

Попап уже собирается в `static/js/map/map_popups.js` через `buildPropertyPopupHtml(property)`.

План:

1. Не создавать новый шаблон попапа.
2. Переиспользовать существующую верстку, чтобы сохранить:
   - фото;
   - цену;
   - название;
   - локацию;
   - спальни/ванные/площадь;
   - избранное;
   - WhatsApp;
   - ссылку на страницу объекта;
   - цели Метрики.

### 5.2. Разделить hover и click

Сейчас `openPropertyPopup(feature)` используется как click-действие и внутри отправляет цель `catalog_map_marker_click`.

Нужно не смешивать hover и click.

План:

1. Разделить открытие попапа и отправку click-цели.
2. Для hover использовать отдельный сценарий:
   - открыть попап;
   - не отправлять click-цель;
   - при необходимости отправлять отдельную цель только после согласования, например `catalog_map_marker_hover`, но лучше не спамить аналитику hover-событиями.
3. Click оставить как осознанное действие пользователя.

### 5.3. Избежать мерцания

Hover-попапи часто мерцают, если закрывать их сразу при `mouseleave`.

Нужна небольшая state-machine логика:

- `hoveredPropertyId` - объект, над которым сейчас курсор;
- `hoverPopup` - текущий hover-попап;
- `hoverCloseTimer` - таймер отложенного закрытия;
- `isPointerOverPopup` - курсор находится внутри попапа;
- `isPinnedPopup` - попап закреплен кликом.

Поведение:

1. `mouseenter` / `mousemove` по маркеру:
   - отменить таймер закрытия;
   - если объект новый, открыть/обновить попап;
   - подсветить маркер.
2. `mouseleave` с маркера:
   - запустить таймер закрытия.
3. `mouseenter` на DOM попапа:
   - отменить таймер закрытия.
4. `mouseleave` с DOM попапа:
   - запустить таймер закрытия.
5. Click по маркеру:
   - можно закрепить попап;
   - закрепленный попап не закрывается от hover-leave.
6. Click по пустой карте:
   - закрыть закрепленный и hover-попап.

### 5.4. Touch detection

Hover включаем только для устройств с мышью.

Ориентир:

- `window.matchMedia('(hover: hover) and (pointer: fine)')`.

Если условие не выполняется:

- hover-попапи не подключаем;
- оставляем click/tap.

## 8. Критерии приемки

Задачу можно считать выполненной, если:

- на desktop попап появляется при наведении на объект;
- попап не мешает нажимать CTA внутри карточки;
- на mobile поведение не ухудшилось;
- объектные кластеры не отображаются;
- объекты с одинаковыми или близкими координатами визуально разнесены;
- разнос маркеров не меняет координаты в базе;
- карта не деградировала по скорости на реальных данных;
- визуальное поведение согласовано с клиентом на 3 сценариях:
  - несколько объектов в одном проекте;
  - плотная зона с большим количеством объектов;
  - обычная зона с одиночными объектами.

## 9. Риски и решения

| Риск | Что может пойти не так | Как снизить риск |
| --- | --- | --- |
| Визуальный шум | После отключения кластеров карта станет перегруженной | Уменьшить маркеры на дальнем zoom, грузить по bounds, добавить лимиты |
| Мерцание попапа | Попап закрывается при движении мыши к карточке | Добавить задержку закрытия и hover-lock на DOM попапа |
| Ложная география | Сильно сдвинутый маркер выглядит как другой адрес | Ограничить радиус сдвига и не менять реальные координаты |
| Просадка FPS | Много маркеров без кластеров тормозят карту | Проверить на продовых данных, при необходимости оптимизировать payload |
| Конфликт hover/click | Hover открывает одно, click закрепляет другое | Явно разделить hover-popup и pinned-popup состояния |
| Мобильный UX | Hover-логика ломает touch | Включать hover только для `(hover: hover) and (pointer: fine)` |
