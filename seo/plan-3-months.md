# План роста органического трафика Undersun Estate (3 месяца)

Цель: довести среднесуточный органический трафик до 100 посетителей из Яндекса, Google и Bing за 12 недель. Ниже перечислены детализированные шаги по месяцам с ожидаемыми результатами и метриками контроля.

## Месяц 1. Техническое SEO и базовая видимость

1. **Каноникал и пагинация**
   - **Реализовать динамический `<link rel="canonical">`.**

     | | |
     | --- | --- |
     | **Текущая проблема** | Каноникал формируется как «схема + хост + путь» без query string (`templates/base.html:13-38`, `apps/core/context_processors.py:33-54`). Любые комбинации фильтров/пагинации (например, `/property/?deal_type=sale&district=bangtao&page=3`) указывают на базовый URL, поэтому поисковики рассматривают их как дубликаты и не ранжируют по специфичным запросам. |
     | **Вариант решения** | В `seo_context` вычислять canonical, учитывая только «разрешённые» параметры (`deal_type`, `property_type`, `district`, `location`, `bedrooms`, `build_status`, `page`). Остальные параметры (`sort`, `map_view`, `currency`) нормализовать до базового вида. Для страниц >1 добавлять `?page=N`, если другие параметры отсутствуют; для параметров без отдельного интента (например, `map_view=true`) возвращать базовый URL. Логику вынести в helper и переиспользовать на блогах/локациях. |
     | **Планируемый результат** | Появятся уникальные canonical для релевантных комбинаций («виллы в Бангтао для аренды», «кондо в Ката до $500k»). Это увеличит количество проиндексированных страниц, снизит число дублей в Search Console/Яндекс.Вебмастере и расширит спектр ключей в выдаче. |

   - **Добавить `rel="prev"/"next"` для пагинации** (Google официально не использует их с 2019 года, но атрибуты полезны для Bing/Яндекс и для UX).

     | | |
     | --- | --- |
     | **Текущая проблема** | В `templates/properties/includes/list/list_pagination.html` и других пагинируемых шаблонах отсутствуют `<link rel="prev">/`next`>. Bing и Яндекс хуже понимают структуру серий, а браузеры не получают подсказку для prefetch. |
     | **Вариант решения** | Передавать в шаблон URL предыдущей и следующей страниц (уже нормализованные) и выводить `<link rel="prev">`, когда `page > 1`, и `<link rel="next">`, когда `page < paginator.num_pages`. Разместить логику в `base.html` или в блоке `extra_meta`, чтобы переиспользовать в каталоге, блоге и локациях. |
     | **Планируемый результат** | Пагинация станет связанной, что облегчит индексацию глубокой части списков в Bing/Яндекс и улучшит UX (prefetch, сторонние расширения). |

   - **Проверить корректность** на `/property/`, `/blog/`, `/locations/`.

     | | |
     | --- | --- |
     | **Текущая проблема** | После внедрения новой логики нужно убедиться, что canonical/prev/next формируются одинаково во всех пагинируемых разделах: общий каталог, аренда/продажа, типы, блог (категории/теги/поиск), список районов и локаций. Сейчас `seo_context` не учитывает специфику отдельных view. |
     | **Вариант решения** | Провести ручные и автоматические проверки (`?page=2`, фильтры, разные языки). Добавить smoke-тесты или unit-тесты для ключевых view, задокументировать корректные URL в чек-листе. |
     | **Планируемый результат** | Единая стратегия canonical/пагинации во всех разделах → меньше ошибок, стабильная индексация любого типа контента, отсутствие «некорректных каноникал» в отчётах. |

2. **robots.txt и индексирование**
   - **Обновить директивы robots.txt.**

     | | |
     | --- | --- |
     | **Текущая проблема** | Текущий `templates/robots.txt:1-11` содержит только базовый `Disallow` и один `Clean-param`. Нет строки `Host`, несколько sitemap и подавляющего большинства параметров фильтра (`deal_type`, `property_type`, `district`, `location`, `min_price`, `max_price`, `bedrooms`, `amenities`, `build_status`, `sort`, `map_view`). Яндекс индексирует дубли URL с параметрами, Bing видит разные зеркала. |
     | **Вариант решения** | Расширить файл: добавить `Host`, `Sitemap` с индексом, перечислить Clean-param для всех безопасных GET, явно разрешить корень и закрыть `map_view`. Вынести комментарии, чтобы команда знала, какие параметры допустимы. |
     | **Планируемый результат** | Роботы будут правильно понимать главное зеркало и игнорировать мусорные параметры. Снизится количество «Дубли строк URL» в Яндекс.Вебмастере и ускорится переиндексация фильтров. |

   - **Закрыть служебные AJAX-эндпоинты.**

     | | |
     | --- | --- |
     | **Текущая проблема** | `/property/ajax/*` и другие JSON/админ маршруты доступны для индексации; Метрика показывает заходы роботов на AJAX, что расходует краулинговый бюджет и может приводить к ошибкам 403. |
     | **Вариант решения** | Добавить `Disallow: /property/ajax/` и другие служебные префиксы (`/admin-ajax/`, `/data-import/` и т.д.), проверить, что публичные API защищены метками `X-Robots-Tag: noindex`. |
     | **Планируемый результат** | Поисковики сосредоточатся на витринных страницах, а отчёты по crawl errors очистятся от шумных эндпоинтов. |

3. **Sitemap-архитектура**
   - **Разделить sitemap на тематические файлы.**

     | | |
     | --- | --- |
     | **Текущая проблема** | Сейчас генерируется единый sitemap с тысячами URL (`apps/core/views.py:507-574`). Он растёт и уже близок к лимитам 50k URL/50 МБ, а также не позволяет приоритезировать важные разделы. |
     | **Вариант решения** | Создать индекс-карту и отдельные файлы: `pages`, `properties`, `locations`, `blog`, `amp`, `updates`. Хранить size <45k URL, обновлять lastmod и priority. |
     | **Планируемый результат** | Поисковики смогут быстрее находить нужные типы страниц; проще мониторить ошибки (например, только `properties`). |

   - **Добавить районные и локальные страницы.**

     | | |
     | --- | --- |
     | **Текущая проблема** | Разделы `/locations/` и `PropertyType` плохо представлены в sitemap, из-за чего часть страниц не попадает в индекс. |
     | **Вариант решения** | Включить все районы, локации, типы и их AMP/альтернативы, очищая URL от UTM и `?page=` для канонической формы. |
     | **Планируемый результат** | Поисковые системы гарантированно увидят весь ассортимент локальных страниц, что ускорит рост видимости по геозапросам. |

4. **IndexNow и пинги**
   - **Автоматизировать отправку URL.**

     | | |
     | --- | --- |
     | **Текущая проблема** | На сайте есть ключ IndexNow, но нет автоматической отправки URL при обновлении объектов/локаций/статей, поэтому Bing/Яндекс получают изменения только после переобхода sitemap. |
     | **Вариант решения** | Добавить сигнал в Django (post_save/post_delete) для Property, Location, BlogPost: отправлять URL в IndexNow API пачками по 100. Логировать статус. |
     | **Планируемый результат** | Изменения попадут в выдачу за часы, а не за дни; Bing Webmaster покажет стабильную очередь IndexNow. |

   - **Пинговать sitemap и YML.**

     | | |
     | --- | --- |
     | **Текущая проблема** | После регенерации sitemap/Yandex YML их приходится пинговать вручную, иначе Яндекс задерживает обновление карточек. |
     | **Вариант решения** | Скрипт/management command для отправки `https://yandex.com/ping?sitemap=...` и аналогов в Google/Bing + загрузка YML через API Яндекс.Недвижимости. |
     | **Планируемый результат** | Максимально быстрый апдейт лент и отсутствие устаревших объектов в агрегаторах. |

5. **Главная и внутренний линкинг**
   - **Вернуть блоки «Новые объекты» и «Районы».**

     | | |
     | --- | --- |
     | **Текущая проблема** | На `templates/core/home.html` блоки новых объектов/районов закомментированы. Главная страница не отдает свежие внутренние ссылки, что снижает crawl depth и CTR по локациям. |
     | **Вариант решения** | Разкомментировать блоки, сделать их динамическими (последние 4 объекта по типам, топ-районы), добавить CTA. |
     | **Планируемый результат** | Главная станет «передатчиком веса» на свежие листинги и локации; ожидается рост посещений внутренних страниц и улучшение index coverage. |

   - **Усилить рекомендации в каталоге и карточках.**

     | | |
     | --- | --- |
     | **Текущая проблема** | Блоки `catalog_seo_block` выводят лишь статичный текст, а «Похожие объекты» ограничены 2-3 ссылками. Мало перелинковки на соседние районы/типы. |
     | **Вариант решения** | Расширить SEO-блок: добавить списки ссылок на смежные типы, FAQ, кнопки «Показать на карте». В карточках — вставить блок «Популярные районы рядом» и выводить 6+ похожих объектов. |
     | **Планируемый результат** | Пользователи и роботы будут переходить на большее число страниц за сессию; улучшится распределение PageRank внутри каталога. |

**KPI и майлстоуны месяца 1**

## Месяц 2. Контент и целевые интенты

1. **Лендинги районов и типов**
   - **Раскатать SEO-блоки для связок «тип + район + сделка».**

     | | |
     | --- | --- |
     | **Текущая проблема** | Сейчас `SEOContentBlock` покрывает лишь общий каталог. Для специфичных комбинаций («виллы в Бангтао на продажу») нет уникальных текстов и заголовков, поэтому страницы проигрывают конкурентам. |
     | **Вариант решения** | Создать минимум 15 активных блоков со своим h1, описанием, вставить их в шаблоны каталога по условиям фильтра. |
     | **Планируемый результат** | Появятся тематические посадочные под ключевые запросы → рост релевантности и CTR из выдачи. |

   - **Наполнить лендинги контентом и конверсией.**

     | | |
     | --- | --- |
     | **Текущая проблема** | На большинстве страниц каталога нет подробных описаний, FAQ и CTA — пользователь не понимает ценность района. |
     | **Вариант решения** | Для каждого лендинга подготовить ≥1 000 знаков текста, галерею, чек-лист преимуществ, блок FAQ, формы и быстрые CTA. |
     | **Планируемый результат** | Улучшение поведенческих метрик и конверсии, дополнительная разметка FAQ для выдачи. |

2. **Мультиязычный блог**
   - **Сформировать контент-план на 12 статей.**

     | | |
     | --- | --- |
     | **Текущая проблема** | Блог обновляется нерегулярно, темы дублируют друг друга, нет охвата вопросов о релокации/инвестициях. |
     | **Вариант решения** | Утвердить план публикаций RU/EN/TH по темам рынок, налоги, инвестиции, сравнения типа жилья, истории релокации. |
     | **Планируемый результат** | Стабильный поток нового контента → рост входящих запросов информационного типа. |

   - **Оптимизировать структуру статей.**

     | | |
     | --- | --- |
     | **Текущая проблема** | Статьи почти без структурированных данных и внутренних ссылок, что ограничивает rich snippets. |
     | **Вариант решения** | Добавить FAQ Schema, Article/HowTo JSON-LD, проставить внутренние ссылки на объекты и услуги. |
     | **Планируемый результат** | Появление расширенных сниппетов в SERP, рост переходов и времени на сайте. |

3. **FAQ и структурированные данные**
   - **Расширить schema.org для ключевых страниц.**

     | | |
     | --- | --- |
     | **Текущая проблема** | На `/contact/` нет LocalBusiness/RealEstateAgent schema, FAQ блоки не размечены, Product schema в карточках отдаёт только THB. |
     | **Вариант решения** | Добавить соответствующую разметку, указать часы работы, телефоны, FAQ; в Product включить USD/THB/RUB и `priceValidUntil`. |
     | **Планируемый результат** | Больше сигналов доверия и релевантности для поисковиков; повышение CTR за счёт FAQ snippets. |

4. **UX для фильтрации**
   - **Добавить поисковые пресеты и сохранения.**

     | | |
     | --- | --- |
     | **Текущая проблема** | Фильтры требуют ручного ввода значений, нет быстрых сценариев («Виллы до $500k»). Пользователи часто бросают поиск. |
     | **Вариант решения** | Внедрить пресеты по бюджету/площади, кнопки «Сохранить поиск» (email/мессенджер), хэштаги для популярных запросов. |
     | **Планируемый результат** | Увеличение глубины просмотра и количества заявок из каталога. |

   - **Логировать внутри поисковые запросы.**

     | | |
     | --- | --- |
     | **Текущая проблема** | Нет статистики по вводу пользователей в поле поиска, поэтому сложно расширять семантику. |
     | **Вариант решения** | Добавить серверный логгер (модель + админка) для запросов, фильтровать персональные данные. |
     | **Планируемый результат** | Появится real-time понимание спроса → быстрее добавляем новые фильтры и статьи. |

5. **Медиа и образовательные материалы**
   - **Создать видеогайды и внедрить VideoObject.**

     | | |
     | --- | --- |
     | **Текущая проблема** | Видео-контента нет, хотя аудитория активно ищет обзоры районов и процессов покупки. |
     | **Вариант решения** | Записать минимум 3 ролика (обзор района, этапы сделки, налоги), загрузить на YouTube, встроить на сайт и оформить `VideoObject` schema. |
     | **Планируемый результат** | Присутствие в видеовыдаче Google/Яндекс, дополнительные переходы и повышение доверия. |

## Месяц 3. Авторитет и дистрибуция

1. **Площадки объявлений**
   - **Расширить дистрибуцию через YML.**

     | | |
     | --- | --- |
     | **Текущая проблема** | YML-фид существует, но используется только для Яндекс (и то не автоматизировано). Международные площадки не получают актуальные данные. |
     | **Вариант решения** | Подключить экспорт в Яндекс.Недвижимость, Циан, Домклик, Avito, ThaiProperty, ListGlobally, Rightmove Overseas; настроить ежедневный cron обновлений. |
     | **Планируемый результат** | Резкий рост внешних источников ссылок и лидов, дополнительный краулинг объектов через авторитетные каталоги. |

   - **Отслеживать эффективность каналов.**

     | | |
     | --- | --- |
     | **Текущая проблема** | Нет аналитики по трафику/лидам с каждого агрегатора. |
     | **Вариант решения** | Добавить UTM-метки, вебхуки и отдельные пайплайны в CRM для заявок из площадок. |
     | **Планируемый результат** | Прозрачное понимание ROI каждого партнёра, возможность перераспределять усилия. |

2. **Репутация и E-E-A-T**
   - **Собрать и опубликовать отзывы.**

     | | |
     | --- | --- |
     | **Текущая проблема** | В Google Business Profile, Яндекс.Справочнике и Bing Places мало отзывов, что снижает доверие и локальный рейтинг. |
     | **Вариант решения** | Организовать кампанию по сбору отзывов клиентов (email/post-sale опрос), модерация и публикация в карточках и блоге. |
     | **Планируемый результат** | Рост среднего рейтинга, появление релевантных отзывов в выдаче по брендовым запросам. |

   - **Оформить кейсы и экспертный контент.**

     | | |
     | --- | --- |
     | **Текущая проблема** | На сайте мало подтверждений компетенций (case studies, сертификаты, медиа-упоминания). |
     | **Вариант решения** | Разместить кейсы с цифрами (доходность, сроки сделки), добавить блок «СМИ о нас», обновить страницы команды. |
     | **Планируемый результат** | Повышение E-E-A-T и доверия со стороны поисковиков и клиентов. |

3. **Digital PR и партнёрства**
   - **Провести outreach-кампанию.**

     | | |
     | --- | --- |
     | **Текущая проблема** | Внешних ссылок мало, домены-доноры сосредоточены в RU-зоне, нет локальных упоминаний. |
     | **Вариант решения** | Связаться с медиа и ассоциациями Пхукета, подготовить 3–5 гостевых материалов/интервью, договориться о ссылках на лендинги. |
     | **Планируемый результат** | Рост авторитетности домена, выход в локальные подборки и тематические обзоры. |

   - **Включиться в expat-комьюнити.**

     | | |
     | --- | --- |
     | **Текущая проблема** | На форумах Phuket expat, ThaiVisa и т.п. нет официального присутствия бренда, хотя там целевая аудитория. |
     | **Вариант решения** | Участвовать в мероприятиях, размещать экспертные ответы/гайды с ссылкой на сайт, предлагать партнёрства организаторам. |
     | **Планируемый результат** | Дополнительные упоминания, переходы и лиды от комьюнити, рост узнаваемости. |

4. **Оптимизация конверсий**
   - **Протестировать новые точки контакта.**

     | | |
     | --- | --- |
     | **Текущая проблема** | На сайте ограниченный набор форм (email + телефон), пользователи просят мессенджеры. |
     | **Вариант решения** | Добавить кнопки WhatsApp/Telegram, «Заказать звонок», многошаговые формы, протестировать sticky-CTA. |
     | **Планируемый результат** | Повышение конверсии из органики и уменьшение отказов. |

   - **Передавать оффлайн-конверсии в GA/Метрику.**

     | | |
     | --- | --- |
     | **Текущая проблема** | Real estate сделки закрываются оффлайн, но данные не возвращаются в аналитику, что искажает оценку каналов. |
     | **Вариант решения** | Экспортировать подтверждённые сделки из CRM обратно в GA4/Метрику как offline conversions. |
     | **Планируемый результат** | Полная картина воронки и возможность оптимизировать по реальному revenue. |

5. **Мониторинг и масштабирование**
   - **Регулярно анализировать индексацию.**

     | | |
     | --- | --- |
     | **Текущая проблема** | Ошибки индексации замечаются только когда падает трафик, логи не анализируются. |
     | **Вариант решения** | Еженедельно проверять Search Console/Вебмастер, логи `/logs`; устранять soft 404, редирект-петли, медленные страницы. |
     | **Планируемый результат** | Ранняя диагностика проблем → стабильный рост видимости. |

   - **Расширять семантику и языки.**

     | | |
     | --- | --- |

     | **Планируемый результат** | Постоянное расширение охвата и подготовка к новым рынкам. |
